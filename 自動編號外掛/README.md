## 功能說明

1. 使用者於符合條件的狀態下按下「儲存」。
2. 外掛跳出**確認訊息**（採用 SweetAlert2，未載入時退回瀏覽器原生 confirm）。
3. 確認後記錄存檔。
4. 記錄**儲存成功**的當下，外掛依「供應商分類」決定編號規則：
   - **發號類**（境外、NX 集團等）→ 向 Counter App 以 **revision 樂觀鎖** 遞增取號（如 `GO000001`），回寫至編號欄位。
   - **抄錄類**（國內供應商）→ 走**旁路**，直接抄錄既有欄位（如 8 碼統一編號），不經過 Counter App。
5. 完成後顯示成功訊息，並重新整理頁面以呈現編號。

> 採「儲存成功後才發號」可避免使用者取消或驗證失敗造成跳號（詳見設計文件第五節）。

## 設計對應

| 設計文件概念 | 外掛實作 |
| --- | --- |
| 複合鍵（app_id + category_key）定位發號機 | 執行時自動帶入 `kintone.app.getId()`，查詢使用 `source_app_id` + `category_key` |
| revision 樂觀鎖防止撞號 | `issueSerial()` 以帶 `$revision` 的 PUT 更新，遇 `GAIA_CO02` 自動重試（次數可設定） |
| 週期歸零（NONE/YEARLY/MONTHLY/DAILY） | `getPeriodTag()` 比對 `period_tag`，跨週期時歸零，動作包覆於樂觀鎖內 |
| 國內供應商走旁路抄錄統一編號 | 分類規則採「抄錄欄位」模式並搭配 `taxId8` 驗證 |
| 純前端無後端、Token 風險 | Token（選填）加密存於外掛代理設定，執行時由 kintone 伺服器注入、前端不接觸明文；即使未設 Token，安全性仍依賴 kintone 權限與編號欄位唯一性把關（詳見設計文件第八節） |

## 安裝與設定

### 1. 上傳外掛
系統管理 → 外掛程式管理 → 匯入 `plugin.zip`。

### 2. 加入 App
目標業務 App → App 設定 → 外掛程式 → 勾選本外掛 → 更新 App。

### 3. 設定畫面（齒輪圖示）

第 1 步（計數器）全外掛共用；第 1 步下方的**分頁**列出這張表單的每一組號碼，第 2～5 步編輯的是目前選中的那一組。
只有一個號碼的表單維持一組即可，畫面與舊版相同。

| 區塊 | 欄位 | 說明 |
| --- | --- | --- |
| **1. 計數器** | Counter App ID | 共用發號中台的 App ID |
| | Counter API Token | 建議填寫，須具「記錄編輯」權限，使用者即使無權限亦能發號。🔒 按「儲存」後加密存放於 kintone 伺服器，一般使用者無法讀取 |
| | 本 App Token | 選填，供回寫編號使用；流程推進後使用者已無編輯權時需要。🔒 同上，加密存放 |
| | active 查詢條件 | 預設 `active in ("啟用")`，須對應 Counter App 的啟用值 |
| | 併發重試次數 | 預設 5（進階設定，各組共用） |
| **2. 業務欄位** | 編號欄位 | 寫入目標（建議勾選「值的唯一性」） |
| | 分類欄位 | 決定套用哪條規則（如「供應商分類」） |
| **3. 觸發** | 觸發時機 | create.submit／edit.submit／process.proceed，可複選 |
| | 確認訊息文字 | 儲存前彈出的提示文字 |
| | 狀態條件 / 到狀態 / 動作名稱 | `*` 表示任意，或限定特定狀態才發號 |
| **4. 分類規則** | 分類值 | 須與分類欄位選項完全相同；填 `*` 代表「任意非空分類值」（先精確比對、找不到才用萬用） |
| | 計數器代碼 | Counter App 的 `category_key`。留空＝直接用分類值；**多列填相同代碼即共用同一台計數器**（序號連續不重號）。可用 `{欄位代碼}` 樣板，見下方「計數器台數很多時」 |
| | 模式 | 發號 / 抄錄 |
| | 來源欄位（抄錄用） | 抄錄模式填寫來源欄位代碼；發號模式留空 |
| | 驗證 | 抄錄模式可選「統一編號 8 碼」 |
| **5. 代碼對照表**（選用） | token 名稱 | 可在 `number_format` 中以 `{名稱}` 使用，例：`level` |
| | 來源欄位 | 要轉成代碼的欄位，例：事故級別 |
| | 對照 | 一行一組「欄位值=代碼」，例：`一般事故=G`；`事業本部*=A`＝開頭相符；`*=Z`＝其餘任意值（v1.6.1） |

### 設定範例（對應設計文件四筆計數器）

| 分類值 | 模式 | 參數 |
| --- | --- | --- |
| 國內供應商 | 抄錄欄位 | `統一編號`（來源欄位代碼） |
| 境外供應商 | 發號 | （無；用分類值本身） |
| NX集團供應商 | 發號 | （無；用分類值本身） |

> 一般供應商 App（685）與營運供應商 App（686）套用**同一份外掛**，`source_app_id` 自動帶入，兩者互不衝突。

### 如何調整編號樣式（RN000001 → RN-001）

**樣式不設於本外掛，亦無須修改程式**。樣式由 **Counter App 該筆發號機的 `number_format` 欄位**決定，後台維護人員直接編輯該筆記錄即可：

| 想要的號碼 | `number_format` | `pad` |
| --- | --- | --- |
| `RN000001`（預設） | 留空 或 `{prefix}{seq}` | 6 |
| `RN-001` | `{prefix}-{seq}` | 3 |
| `RN-001`（鎖 3 碼） | `{prefix}-{seq:3}` | 任意 |
| `2026-RN-0001` | `{YYYY}-{prefix}-{seq}` | 4 |

可用 token：`{prefix}`、`{seq}`、`{seq:N}`（補零 N 位）、`{period}`、`{YYYY}`/`{YY}`/`{MM}`/`{DD}`，以及由「代碼對照表」定義的自訂 token。完整說明請見[設計文件 §3.4](../CLAUDE.md)。

### 計數器台數很多時：用 `{欄位代碼}` 樣板批量涵蓋

當「要用哪一台計數器」取決於記錄上的多個欄位，逐條列舉會讓設定畫面爆炸。此時把「計數器代碼」寫成樣板即可。

**實例：MIS作業申請單的設備代號**
編號規則為 `NX` ＋ 設備種類 ＋（年碼｜`99`）＋ 3 碼流水，依「設備種類 × 設備需求」分組 → 18 種類 × 2 需求 ＝ **36 台計數器**。設定只需**兩條規則**：

| 分類值（分類欄位＝`設備需求`） | 計數器代碼 | 模式 | 執行期解析成 |
| --- | --- | --- | --- |
| `新增` | `{設備種類}新增` | 發號 | `N1新增`、`P1新增`… |
| `修改` | `{設備種類}修改` | 發號 | `N1修改`、`P1修改`… |

`刪除` 不建規則，因此不會發號。

**Counter App 的 36 筆發號機用工具批量建立**（不必手動一筆筆開）。兩種方式擇一：

#### 方式 A（推薦）：掛在 Counter App 上的按鈕

把 `編號計數器/發號機批量建檔.js` 上傳到 **編號計數器 App** 的「JavaScript / CSS 自訂」，
清單頁就會多一顆「批量建立發號機」按鈕：填業務 App ID → 預覽 → 確認建立。

走登入者自己的 session 權限，**不需要 API Token，也不用設 `.env`**。

#### 方式 B：Node 腳本

```bash
node tools/seed-counters.mjs --source-app=<業務AppID> --counter-app=<CounterAppID>
```

預設是 dry-run 只印出將建立的內容，確認無誤後加 `--apply` 才實際寫入。
認證資訊寫在專案根目錄的 `.env`：

```
KINTONE_BASE_URL=https://xxx.cybozu.com
KINTONE_USERNAME=...
KINTONE_PASSWORD=...
```

#### 兩者共通的行為

**直接讀業務 App 的表單設定**取得「設備種類」的實際選項（不寫死清單），
所以日後表單新增設備種類，重跑一次即可補上缺的計數器 —— **冪等**，
已存在的會自動略過，不會重複建檔、也不會覆蓋既有 `current`（不會把號碼歸零）。

#### ⚠ 接續既有編號（方式 A、B 皆已實作）

若業務 App 已經有編號在跑，**`current` 不能從 0 開始**，否則第一次發號就會產生
`NXN126001` 而與現有記錄撞號。兩種方式都會在建檔前掃描業務 App 現有的編號欄位，
依各台計數器的 `number_format` 推算出「目前已發到第幾號」，把 `current` 設成該值
（方式 B 用 `--number-field=` 指定要掃描的欄位，預設 `設備代號`）。

同時 **`period_tag` 必須設成當期標記**（`YEARLY` → `2026`）。若留空，外掛第一次發號時
`nowTag !== lastTag` 成立 → 判定跨週期 → 號碼歸零到 1，掃描就白做了。

判定邏輯與 `desktop.js` 的 `getPeriodTag()` 一致，三處（外掛、方式 A、方式 B）若有修改須同步。

掃描時會自動排除「開頭吻合但流水號位數不符」的舊制編號（不列入計算，但會在預覽中列出提醒）；
`YEARLY` 的計數器也只會計入**當年度**的編號，去年的 `NXN125025` 不會影響今年的起算點。

> 若樣板用到的欄位在該筆記錄為空（例如沒選設備種類就儲存），發號會**中止並提示**，不會產生 `NX26001` 這種少了設備種類的錯號。

#### `reset_cycle` 支援中英文選項

`reset_cycle` 是各 Counter App **自己建立**的下拉欄位，選項文字由管理者自己決定，
kintone 會嚴格檢查寫入值是否存在於欄位的選項清單裡，寫錯字串會被整批拒絕
（錯誤訊息類似 `The value, "YEARLY", is not in options.`）。

外掛與兩支批量建檔工具都認得下面兩種寫法，**擇一設定 Counter App 的下拉選項即可**：

| 語意 | 英文常數 | 中文選項 |
| --- | --- | --- |
| 不歸零，永久累加 | `NONE` | 不重置 |
| 每年歸零 | `YEARLY` | 每年重置 |
| 每月歸零 | `MONTHLY` | 每月重置 |
| 每日歸零 | `DAILY` | 每日重置 |

批量建檔工具會在動手寫入前，先確認本次要用到的每個週期都能在 Counter App 的
`reset_cycle` 選項裡找到對應項目，找不到就直接列出缺哪個選項再中止——
不會讓 kintone 用看不出原因的「輸入錯誤」擋下整批寫入。

> ⚠ 若欄位用了上表以外的第三種寫法（例如「每年重設」），外掛在**讀取**時仍會落入
> 「不重置」的行為（不歸零、永久累加），但**不會報錯**，是不容易發現的靜默錯誤。
> 請把選項文字對齊上表其中一欄，或修改三處程式碼（`desktop.js`／`mobile.js`／
> 兩支批量建檔工具）裡的 `RESET_CYCLE_ALIASES` 對照表加入新別名。

### 一張單要產生多個編號（子表格逐列發號）

當一張申請單的表格裡每一列都要一個編號（例：設備清單 10 列 → 10 個設備代號），
在設定畫面第 2 步把「號碼的產生方式」改成 **「表格的每一列各一個號碼」**，
再指定表格欄位；此時「存放號碼的欄位」與「判斷種類的欄位」改填**表格內**的欄位代碼。

判斷種類的欄位若其實放在表單本體（不在表格裡）也沒關係 —— 外掛的取值順序是
**先找列內、找不到再找表頭**，所以「設備種類在列內、設備需求在表頭」這種混合擺法可直接運作，
設定上不必指定每個欄位在哪一層。

#### 效能：批次預留

同一台計數器的多列**只做一次樂觀鎖**，一口氣預留整段連號，呼叫次數與列數脫鉤：

| 情境 | API 呼叫次數 |
| --- | --- |
| 10 列、3 種計數器 | **8 次**（讀記錄 1 ＋ 計數器 3×2 ＋ 回寫 1） |
| 若逐列各發一次號 | 22 次 |

列數再多也只看「用到幾種計數器」，20 列同種類仍是 2 次。

#### 防呆

- **先規劃、再取號**：所有列的計數器代碼與抄錄值會先全部解析完，任一列有問題（例如某列
  設備種類沒填）就在儲存前整批中止，**一個號碼都不會被消耗**，不會發生「前三列已扣號、
  第四列才報錯」的跳號。
- 已有編號的列不會重發。
- 回寫時會送出**所有列並帶上原本的 `id`**——kintone 的子表格是整包覆蓋，
  少送或沒帶 id 會導致既有列被刪除或重建。

#### ⚠ 唯一性防線

kintone 的**「值的唯一性」不支援子表格內的欄位**，因此不變量 I6 那道最後防線在此模式下不存在。
防撞號僅靠 revision 樂觀鎖與批次預留（機制本身可靠）。建議補上兩項零成本的加固：

**① Counter App 的 `current` 設為唯讀**，且只開放管理員編輯 → 擋掉「有人手動改小 current」。

**② 新增 `unique_key` 欄位承載複合鍵的唯一性** → 擋掉「同一個 App 重複建了同一台計數器」。

> ⚠ **不可以直接對 `category_key` 勾唯一性。** 發號機的鍵是**複合鍵
> `(source_app_id, category_key)`** —— 不同業務 App 本來就會有相同的 `category_key`
> （App 123 與 App 456 都可以有 `N1新增`），勾下去會把合法記錄擋掉。
> 而 kintone 的唯一性只能套在單一欄位，沒有複合唯一約束。

作法：Counter App 新增一個**文字（單行）**欄位、欄位代碼 `unique_key`，內容為
`source_app_id-category_key`（例：`123-N1新增`），唯一性勾在**這個欄位**上。

`發號機批量建檔.js` 會自動處理：

- 批量建檔時一併寫入 `unique_key`（Counter App 沒有這個欄位時自動略過）
- 管理者手動新增／修改計數器時，於 submit 自動組出 `unique_key`，不會出現破口
- 清單頁提供「**補寫 unique_key**」按鈕，把既有記錄一次補齊
  —— **勾唯一性之前必須先跑這個**，否則一堆空值會被視為重複而勾不起來
- 補寫時會順便偵測「同一個 App 有兩台相同 `category_key`」，有的話中止並列出來請人工處理
  （那正是會造成重號的情況）

**③ 事後重號檢查**：`重號檢查.js`（同樣掛在編號計數器 App）提供清單頁按鈕，
掃描業務 App 的編號，列出重複的號碼出現在哪幾筆記錄的哪幾列，並一併回報空白編號。

刻意做成「事後檢查」而非「發號時驗證」：檢查不在發號的關鍵路徑上，
壞掉也只是檢查沒跑，不會有人送不出單；若改成每次發號都去驗證，
就多了一個會擋住使用者存檔的失敗點，那是維運上最擾民也最難查的一種故障。

此外，`發號機批量建檔.js` 的預覽會偵測**既有計數器的 `current` 落後於實際最大號**
——那代表下次發號就會撞號，會直接標示出應該調整成多少。

#### 批量建檔時，其他欄位要填一樣的值

Counter App 若還有本工具不知道的欄位（例如部門、負責人），且**這批建立的每一筆都要填同樣的值**：

- **`發號機批量建檔.js`**：對話框第一步「其他欄位（可選）」，**從下拉選單選欄位**（自動讀取
  Counter App 現有欄位，不必手動輸入代碼、不會打錯字），值仍為自由輸入文字。
  下拉只列出「填一個字串就能寫入」的型別（單行文字、數字、下拉選單、日期等），
  排除子表格、核取方塊、使用者選擇、附件這類需要陣列或物件值的欄位。
- **`tools/seed-counters.mjs`**：`--set=欄位代碼=值`，可重複帶多個（Node 環境無法互動選單，故仍為輸入）。
  ```bash
  node tools/seed-counters.mjs --source-app=123 --counter-app=456 \
    --set=部門=資訊部 --set=負責人=王小明
  ```

兩者都會擋下：值有填卻沒選欄位、同一欄位填兩次、或填到本工具已經在管理的欄位
（`source_app_id`、`category_key`、`prefix`、`pad`、`number_format`、`reset_cycle`、
`period_tag`、`current`、`unique_key`）——這些欄位的值由批量計算而來，自行覆蓋會破壞結果。
`發號機批量建檔.js` 的下拉選單已自動排除這些，`--set` 則於執行時檢查並報錯。

#### 建立失敗時看得懂原因

Counter App 若有本工具不知道、卻被設成**必填**的欄位，建立當下一定會被 kintone 擋下，
但 kintone 的原始錯誤訊息通常只有「輸入錯誤」這種空泛文字，看不出是哪個欄位、缺什麼。

兩種工具都會在**建立前**先檢查 Counter App 的必填欄位，未被涵蓋的話直接列出來，
不必等到建立失敗才知道：

```
以下必填欄位尚未設定值，請在「其他欄位」選擇並填入：
  備註（備註）

以下必填欄位的型別本工具無法自動填值（需要陣列或物件值），
請到 Counter App 的欄位設定將它們改為非必填，或建立後再手動逐筆補值：
  負責使用者（使用者・USER_SELECT）
```

前者（單行文字、數字、下拉選單等）可直接用「其他欄位」／`--set` 補上；
後者（使用者選擇、核取方塊、附件…）需要陣列或物件值，本工具無法自動填，
只能請管理者把該欄位改為非必填，或建檔後再手動逐筆補值。

若通過此檢查後**仍然**建立失敗，`發號機批量建檔.js` 與 `tools/seed-counters.mjs`
都會把 kintone 回應中的逐欄位錯誤明細印出來（而不是只顯示「輸入錯誤」），例如：

```
建立失敗：入力エラーです。
・unique_key：値の重複禁止に違反しています。
```

`unique_key` 出現在明細裡，代表**該欄位還沒完成 §「複合鍵的唯一性防線」的補寫步驟**
——先跑「補寫 unique_key」再重試。

### 一張表單有好幾個號碼（多組設定）

設定畫面第 1 步下方按「＋ 新增一組號碼」，每一組各自填第 2～5 步。執行時：

- **同一次儲存有好幾組要發號** → 確認訊息只問一次（各組訊息合併），發完後結果彙整成一個視窗。
- **儲存後發號**（create/edit）：逐組依序處理，某一組失敗不影響其他組，失敗的會列在結果視窗裡。
- **流程推進時發號**（process.proceed）：任一組失敗就整個不推進，避免只存到一半的號碼。
- 存檔前會擋下兩種設定錯誤：兩組寫入同一個欄位、兩組使用相同的計數器代碼。

> ⚠ **不同組要用不同的計數器代碼**。計數器以 `(source_app_id, category_key)` 定位，
> 同一個 App 裡兩組都填 `CA` 就會搶同一串流水號、而且號碼樣式也會一樣。
> 名稱上想表達「也是 CA 類」時，加個前綴區隔即可（例：`TOA_CA`），號碼長相由該筆計數器的 `prefix`／`number_format` 決定，不受代碼名稱影響。

#### 實例：貨物事故報告書（App 630）

| | 第 1 組：事故編號 | 第 2 組：東亞貨物編號 |
| --- | --- | --- |
| 號碼樣子 | `2026001-G-CA` | `CA-2610-001` |
| 存放／判斷欄位 | `事故編號`／`事故分類` | `東亞貨物編號`／`通報編號` |
| 產生時機 | 只勾「按下流程動作時」，限定送到 `文件確認` | 勾「新增一筆並儲存時」與「編輯後儲存時」 |
| 分類規則 | 物損事故(貨物)→`CA`、物損事故(設施或其他)→`CA`、搬家行李事故→`HA`、其他事故→`OA` | 通報物損編號→`TOA_CA`（其他選項不建規則＝不發號） |
| 代碼對照表 | `level` ← 事故級別：`一般事故=G`、`重大事故=M` | （無） |

Counter App 對應 4 筆（`source_app_id` 皆為 630）：

| category_key | prefix | pad | number_format | reset_cycle |
| --- | --- | --- | --- | --- |
| `CA`／`HA`／`OA` | 同代碼 | 3 | `{YYYY}{seq}-{level}-{prefix}` | 每年重置 |
| `TOA_CA` | `CA` | 3 | `{prefix}-{YY}{MM}-{seq}` | 每月重置 |

> 既有號碼要接續時，`current` 填目前已用到的最大流水號、`period_tag` 填當期（每年制 `2026`、每月制 `202610`），
> 否則第一次發號會從 1 起跳而撞號。可用 `貨物事故報告書/掃描既有編號_current_20261002.js` 在瀏覽器 Console 算出各台的值。

### 進階範例：號碼要嵌入「逐筆變動」的代碼

事故編號 `2026001-G-CA`（年＋3 碼流水－級別代碼－分類代碼），其中流水號依「年＋分類」分組，級別只是嵌在號碼裡、不影響分組：

1. **分類規則**：4 個分類值各一列，「計數器代碼」分別填 `CA`／`CA`／`HA`／`OA`——兩種物損事故填相同代碼，即共用一台計數器、序號連續。
2. **代碼對照表**：token 填 `level`、來源欄位選「事故級別」、對照填 `一般事故=G` 與 `重大事故=M`。
3. **Counter App** 建 3 筆（CA／HA／OA），`number_format` 皆填 `{YYYY}{seq}-{level}-{prefix}`、`pad`=3、`prefix` 各為 CA／HA／OA、`reset_cycle`=`YEARLY`。

> 若某筆記錄的級別在對照表中查無代碼，發號會中止並提示，不會產生 `2026001--CA` 這種殘缺號碼。

### 代碼依部門決定（組織選擇欄位＋開頭相符，v1.6.1）

**實例：人力需求表的職缺編號** `A26001`（部門代碼＋兩碼年＋3 碼流水）。
所有部門**共用同一串流水號**（`A26001`、`FO26002`、`OC26003`…），部門代碼只是貼在號碼上，不影響分組，
因此 Counter App **只建 1 筆**，部門代碼交給代碼對照表。

| 步驟 | 設定 |
| --- | --- |
| 2. 業務欄位 | 編號欄位 `職缺編號`、分類欄位 `申請單位`（組織選擇） |
| 3. 觸發 | 只勾「新增一筆並儲存時」 |
| 4. 分類規則 | 1 列：分類值 `*`、計數器代碼 `JOBNO`、發號 |
| 5. 代碼對照表 | token `dept`、來源欄位 `申請單位`，對照如下 |

```
事業本部*=A
總務部*=A
併裝中心*=A
營業戰略部*=A
安全品質推動部*=S
航空貨物部*=FO
桃園機場營業所*=FO
新竹營業所*=FO
海運貨物部*=OC
物流部*=L
汽車貨運部*=C
台中營業部*=T
高雄營業部*=KH
聯海*=BC
```

Counter App 1 筆：`category_key`=`JOBNO`、`prefix` 留空、`pad`=3、`number_format`=`{dept}{YY}{seq}`、
`reset_cycle`=每年重置、`period_tag`=當年（如 `2026`）、`current`=當年已用到的最大流水號。

比對規則：

- **完全相同優先**，其次「開頭相符」（多條符合取最長的，與填寫順序無關），最後才是 `*`。
- 組織／使用者／群組選擇比對的是**名稱**，也接受**代碼**（組織改名時，寫代碼的對照不受影響）。
- 選了多個組織時，逐一比對每個組織，先比完全相同、再比開頭相符。
- 欄位空白或都對不到 → 發號中止並提示，計數器不會被推進（不跳號）。

> 由於每個 App 使用各自的 Counter 記錄，**A App 維持 `RN000001`、B App 改為 `RN-001` 互不影響**，這正是「將樣式置於發號機本身」的優點。修改後**毋須重新打包外掛**。

## 重新打包（修改程式後）

修改 `contents/dist/*.js` 後（`desktop.js` 與 `mobile.js` 內容須一致，修改後務必同步），使用 **本外掛專屬私鑰** 重新打包：

```bash
npx @kintone/plugin-packer contents --ppk auto-numbering.ppk --out plugin.zip
```

- 私鑰 `auto-numbering.ppk`（公鑰 `auto-numbering.pub`）為本外掛專用，**請妥善保管、切勿外流**。
- 使用相同的 `.ppk` 可維持相同的 plugin ID，於後台「更新」即可覆蓋升級，且設定會自動保留。
